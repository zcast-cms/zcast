## 1. `+ New Note` button styling breaks into native 3D outset bevel while a draft is open (`zcast` / `zcast-theme-davidhewitson`)
- **Symptom:** When a draft pane is active (`[data-zcast-new-note][data-draft-active="true"]`), the `+ New Note` button renders with Firefox's default 3D beveled `border-style: outset` look.
- **Root Cause:** `.zcast-header-btn` (`<button class="zcast-header-btn" data-zcast-new-note>`) lacks base styling (`appearance: none; border: 1px solid var(--zcast-border); background: transparent; border-radius: var(--zcast-radius); padding: ...`), so setting `border-color: var(--zcast-accent)` in `editor.css:486` reveals the browser's default outset border.
- **Fix:** Style `.zcast-header-btn` cleanly using `--zcast-*` design tokens in `theme.css` (and `editor.css` fallback) matching the pill/minimal editorial chrome, with a subtle muted state when `[data-draft-active="true"]`.

## 2. Text selection inside `[[wikilinks]]` turns unreadable black + allow navigating `[[links]]` while in edit mode (`zcast-editor-inline` / `zcast-theme-davidhewitson`)
- **Symptom A (Black text on dark selection):** Selecting text inside a `[[wikilink]]` in dark mode renders near-black text (`#1d1d1d`) over a dark translucent background.
  - **Root Cause:** `theme.css:164` sets global `::selection { background: var(--zcast-accent); color: var(--zcast-bg); }` (`#1d1d1d` text in dark mode), while `.zcast-editor-prose` / `.zcast-wikilink-text` (or ProseMirror selection) overrides or dims the selection background without overriding `color`.
  - **Fix:** Give `.zcast-editor-prose ::selection` and `.zcast-wikilink-text::selection` explicit high-contrast `background` + `color` tokens (e.g. `background: rgba(255, 255, 255, 0.24); color: var(--zcast-text-strong);` in dark mode and `rgba(0, 0, 0, 0.14); color: var(--zcast-text-strong);` in light mode).
- **Symptom B (Navigating `[[links]]` during edit mode):** Clicking a `[[wikilink]]` while editing currently only places the text caret.
  - **Enhancement:** Support navigating directly to the linked note while staying in edit mode:
    1. **`Cmd+Click` / `Ctrl+Click`** on any `.zcast-wikilink-text` inside the TipTap editor opens that note in a sliding pane to the right (or creates a draft pane if unresolved!).
    2. When the cursor/selection is inside a `[[wikilink]]`, show a compact **"Open ↗"** button on the floating toolbar (or inline link pill) that opens the target card to the right on a single click.

## 3. Close button for non-index rightmost panes (`zcast-theme-davidhewitson`)
- **Requirement:** Users should be able to close the rightmost card pane (or any pane other than the root/index card — never allowing the root/index card to be closed).
- **Fix:**
  - Render a subtle `×` close button (`[data-zcast-close-pane]`) in the top-right chrome of cards when they are not the root/leftmost card (CSS `.zcast-card:first-child [data-zcast-close-pane] { display: none; }` or rightmost-only `.zcast-card:not(:first-child):last-child [data-zcast-close-pane]`).
  - Clicking it cleanly removes the pane (flushing/confirming or discarding if it's an editor pane), smoothly scrolls back to the new rightmost pane, updates breadcrumbs, and syncs `?stack=...` via `history.pushState`.

## 4. Real-time updates for `Linked from` (Backlinks) and renamed title references across open panes (`zcast-editor-inline` + `zcast-kernel`)
- **Requirement:**
  1. When saving a note that adds or removes `[[links]]`, the **Linked from** (`[data-zcast-backlinks]`) section on any other open panes should update in real time without a page refresh.
  2. When renaming a card's title, any other open panes referencing that old title should update both their rendered link text/href **and** their backlinks in real time (and if another open pane is currently in edit mode, refresh safely without clobbering active typing).
- **Fix:**
  - After any `POST` / `PUT` / `DELETE` save in `editor.js`, fetch fresh card fragments (`GET /_zcast/cards/<slug>`) in parallel for the other currently open panes (skipping the card just saved).
  - For each open pane:
    - Always hot-swap its `[data-zcast-card-footer]` (updating **Linked from** backlinks in real time!).
    - If the pane is **not** currently in edit mode (`!editorStates.get(pane)?.editing`), also hot-swap its `[data-zcast-card-body]` so rewritten titles, newly resolved `[[links]]`, and updated excerpts appear immediately!
    - If a card is currently in edit mode, update its cached `renderedHtml` so exiting edit mode shows fresh HTML.
